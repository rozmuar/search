# Виджет рекомендаций

> Сверено с `src/web/recommendations.js` (класс `SearchRecommendationsClass`, глобально доступен как `window.SearchRecommendations`), `SimpleSearchEngine.get_recommendations()` в `src/search/engine_simple.py` и `GET /api/v1/recommendations` в `src/api/main.py`.

Отдельный виджет "рекомендуемое" для любой страницы сайта клиента (обычно — главная). Не связан с `embed.js`/`SearchWidget` — отдельный файл, отдельный класс, свои CSS-классы (`search-recs-*`), можно ставить на одну страницу вместе с виджетом поиска без конфликтов стилей.

Товары показываются в горизонтальном слайдере (`.search-recs-track`, скролл со `scroll-snap`, стрелки-навигация `‹`/`›`) — не сеткой с переносом строк. Стрелки скрываются сами, если все карточки помещаются без прокрутки (`bindSliderNav()`, пересчитывается при ресайзе окна).

## Быстрый старт

```html
<div id="search-recommendations"></div>
<script src="https://ваш-домен/recommendations.js"></script>
<script>
  SearchRecommendations.init({
    apiKey: 'ВАШ_API_КЛЮЧ',
    container: '#search-recommendations',
    category: 'Ноутбуки' // опционально
  });
</script>
```

Готовый сниппет с уже подставленным API-ключом и доменом показывается в личном кабинете, на странице проекта, в карточке "🎯 Рекомендации".

Скрипт отдаётся статикой напрямую через nginx (`location = /recommendations.js` в `nginx.conf`, файл — `src/web/recommendations.js`). Есть и запасной путь — `GET /api/v1/widget/recommendations.js` через FastAPI (тот же файл), но клиентам показывается первый.

## Конфигурация

```javascript
SearchRecommendations.init({
  apiKey: 'sk_...',                 // обязательно

  selector: '#search-recommendations', // или container: '...' - синоним
  category: 'Ноутбуки',             // опционально - раздел сайта (= категория товара);
                                     // можно передать и название категории, и её id из фида
                                     // (categoryId в YML) - см. ниже; если не задан,
                                     // рекомендации не фильтруются по категории
  limit: 8,                         // опционально, 1-50; если не задан - берётся из
                                     // настроек проекта (search_settings.recommendations.limit) или 8
  title: 'Рекомендуем',             // опционально, заголовок над слайдером; '' - убрать заголовок
});
```

Цвета/шрифт/скругление/`showImages`/`showPrices`/`cartCallbackUrl` виджет подтягивает с сервера (`GET /api/v1/widget/{apiKey}/config`) — те же настройки, что уже используются `embed.js`, для визуальной консистентности между поиском и рекомендациями на одной странице.

### `category`: название или id

Раздел можно передать двумя способами — тем, что удобнее в шаблоне сайта:
- **Название категории** — как оно выглядит в фиде/каталоге, например `'Ноутбуки'`. Сравнивается точно (`product.category === category`).
- **Id категории** — значение `categoryId` из YML-фида (`<offer><categoryId>123</categoryId></offer>`), например `'123'`. Полезно на сайтах, где шаблон страницы категории знает только числовой id, а не название. Сравнивается как строка (`String(product.category_id) === String(category)`).

Достаточно совпадения по любому из двух — сервер сам не знает заранее, что именно передал сайт, и проверяет оба поля товара. Id парсится из фида автоматически при загрузке (не для всех фидов есть `categoryId` — если его нет, работает только сравнение по названию).

Если результатов нет (`items: []` — не бывает при пустых настройках, см. этап fallback ниже, но теоретически возможно на проекте без единого товара в наличии) — контейнер скрывается (`display: none`), пустая оболочка не рендерится.

## Что показывается: приоритетная цепочка (waterfall)

Настраивается в личном кабинете на странице проекта, карточка "🎯 Рекомендации" (`search_settings.recommendations` в `PUT /projects/{id}/search-settings`, см. [api.md](api.md)). Реализация — `SimpleSearchEngine.get_recommendations()`.

Источники добавляются по порядку, пока не наберётся `limit` товаров:

1. **Вручную выбранные товары** (`manualProductIds`) — конкретные id, выбранные в ЛК через поиск по названию. Прямой `MGET`, скан по каталогу не нужен.
2. **Фильтры по свойствам** (`attributeFilters`) — правила вида `{"brand": ["Nike", "Adidas"], "params.Цвет": ["Красный"]}`. Внутри одного поля — OR по значениям, между полями — AND. Используется, только если товаров с шага 1 не хватило до лимита.
3. **Популярное по проекту** — на основе уже существующей аналитики кликов/поиска (`analytics:{project_id}:popular_products`), ничего отдельно не собирается. Популярность считается по всему проекту, а не по разделу — фильтр по `category` применяется только при показе.
4. **Просто в наличии** — если ни ручного выбора, ни правил, ни популярности не хватило (или на проекте вообще нет истории кликов), показываются любые товары `in_stock: true` из раздела.

Раздел (`category` в запросе к `/api/v1/recommendations`) фильтрует **все четыре** этапа — рекомендации никогда не показывают товар не из текущего раздела, даже если это самый популярный товар проекта.

Ответ API включает `stages: {manual, attribute, popular, fallback}` — сколько товаров закрыл каждый этап, для отладки настроек.

### Почему это не медленно

Этапы 2 и 4 — единственные, которым нужен полный `SCAN` по товарам проекта (остальные — `MGET`/`ZSET` по готовым id). Если этап 2 запускался (заданы `attributeFilters`), он попутно, за тот же проход, собирает и кандидатов на fallback — если запрос потом всё же доходит до этапа 4, повторного скана не будет. Если этап 2 не запускался вовсе (нет `attributeFilters`) и запрос дошёл до этапа 4, тогда — и только тогда — делается отдельный самостоятельный скан.

## Карточка товара и корзина

Рендер карточки (`renderCard()`) — картинка, название, цена/старая цена, бейдж "Нет в наличии", степпер количества и кнопка "В корзину". Кнопка вызывает `cartCallbackUrl` проекта (тот же колбэк, что настроен для `embed.js` — общий на проект, не отдельный для рекомендаций); если `cartCallbackUrl` не настроен, кнопка не отправляет запрос и пишет предупреждение в консоль.

## Аналитика

Клик по карточке отправляет `POST /api/v1/track/click` с `query: "[recommendation]"` — синтетическая метка вместо пустой строки, чтобы клики по рекомендациям были опознаваемы в аналитике, но всё равно засчитывались в `popular_products` (от которого зависит этап 3 цепочки) — самоусиливающийся цикл: чем чаще кликают по рекомендации, тем вероятнее товар останется в рекомендациях у других посетителей.
